# TI 工程架构与风格约束

## 职责与可读性
- 入口负责初始化与清楚的任务调度；业务流程、板级资源、单设备驱动、基础算法各有归属。目录映射以本项目实际结构为准，不为了统一模板搬目录。
- 保留既有接口、注释和 .clang-format；不因个人风格批量重命名或重排 include。没有规范的新项目先选一份简单风格，沿用即可。
- 函数表达实际职责，不为压行数制造神秘包装链，也不把庞大主流程整体搬进一个文件就宣称完成分层。
- 常量、可调参数、运行状态各有明确归属。模块内部数据优先 static；确有跨模块需求时通过少量接口交换，不到处增加 extern 或让多个模块写同一状态。
- 不用巨大结构体、通用配置系统或设备注册表隐藏耦合。只为实际复用或实际职责拆模块，不预建空文件。
- 业务使用设备接口，不散落操作引脚、寄存器和驱动内部缓存。现有偏离项单独列出，文档完善不自动授权重构。

## TI 配置与实时边界
- 芯片、SDK、编译器、启动文件和链接脚本以当前工程为准。MSPM0、MSP430、C2000 等不同系列不互相套用 API、地址、时钟或编译选项。
- 使用 SysConfig 的工程，以 .syscfg 表达配置意图，并核对生成文件及实际启动调用。发现源配置、生成输出和运行状态不一致时先查明，不盲目重新生成或手改生成区掩盖差异。
- 优先使用本项目已有 SDK/DriverLib 接口；修改 SDK 库、启动文件或链接脚本必须是任务实际需要，不引入 STM32 HAL 等其他平台习惯。
- ISR 保持短小，优先收数据、更新时间戳/计数或产生节拍；日志格式化、显示刷新、阻塞发送和延时放在非实时路径。
- 现有控制环若在定时 ISR 内，先确认执行时间、优先级与周期再决定是否迁移；不在普通修复中擅自更换调度模型。
- volatile 不保证多字段快照一致；有真实并发读写时采用本芯片适用的最小一致性办法，不默认增加队列、RTOS、锁框架。
- 控制计算明确采样周期、单位、正方向与输出尺度。不得靠散落负号、隐式换算或增加补偿掩盖接口/时序错误。

## 复杂度与调试
- 按现象 → 证据 → 根因 → 最小修复 → 验证推进，一次实验尽量只改变一个关键变量。
- 效果不佳且根因未明时，优先安排能区分原因的小实验。不能默认 PID 一定够用，也不能默认加滤波、前馈、分段增益、死区或特殊补偿。
- 新增保护、fallback、watchdog、重试、兼容层或复杂状态前，说明已观察的问题、现有方法为什么不足和最小验证办法，交由 Brain 判断。
- 只实现当前需求和明确的必要安全边界；既有且有依据的必要边界不能为了精简随意去掉。
- 状态机只表达真实离散状态与转换。反例用于检查方案，不自动变成代码分支。
- 验收同时检查功能、改动范围和新增复杂度；没有依据的参数/状态/机制不能因“编译过了”而保留。满足任务目标后停止。

## 上下位机协作
- 对接时核对两端实际实现：帧边界、长度、校验、字节序、字段含义、单位/正方向、发送周期及失效时行为。只约定当前链路需要的内容，不先造通用协议框架。
- 分清测量、预测、目标值和控制输出；无效值不能默默当作零误差，过期样本不能无依据重复累计成执行指令。
- 不把上位机写串口成功当作 MCU 收到，更不能当作控制器采用了这份数据。验收沿发送 → 接收解析 → 控制消费 → 执行输出 → 物理行为逐层取证。
- 只授权一端修改时，另一端可读取核对；协议或控制职责需要跨端变化时由 Brain 明确协调，不自行扩展另一端代码。

## 本项目目录映射与现状
| 位置 | 当前归属 / 后续约束 |
| --- | --- |
| source/main.c | 已有初始化、Aim_Update 调用和定时中断控制；薄入口是增量维护方向，尚未实现 |
| source/app/ | 任务、按键与 UI 编排 |
| source/middle/ | PID、按键等基础单元；不积累板级业务状态 |
| source/Hardware/ | Board、具体外设和旧 Control 模块；沿用接口，不因模板搬迁 |
| source/ti_msp_dl_config.c/.h | 当前 SysConfig 生成配置 |
| libraries/、.cmsis/ | 平台库与核心支持，非普通业务修改区 |

当前 .clang-format 指定 4 空格、禁用 Tab、BreakBeforeBraces: Linux、SortIncludes: false；以该文件为准，不套用 Python 风格。
Hardware/Control 中已有业务控制，main.c 存在多个全局状态且 ISR 内执行控制；这些是当前事实，不代表推荐给新 TI 项目的组织方式。本次只建立规则，不重写旧代码。
